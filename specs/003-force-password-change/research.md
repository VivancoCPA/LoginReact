# Research: Force Password Change Flow

This document details the architectural decisions and security research for the forced password change mechanism.

---

## 1. Context & Challenge

The ASP.NET Core backend `POST /api/auth/change-password` endpoint requires the user's `currentPassword` (the random temporary password generated by the Admin) in order to securely execute a password change.

However, a core user requirement is that **"the user does not need to enter their temporary password again"** once they are redirected to the New Password screen, as they already submitted it to log in.

### Technical Options Evaluated

| Option | Approach | Security Profile | UX Impact |
| :--- | :--- | :--- | :--- |
| **1. Session Storage** | Store `currentPassword` in browser `sessionStorage` during login redirection. | ⚠️ **Medium-Low**: Vulnerable to XSS or browser history inspections. | Excellent |
| **2. Temporary Cookie** | Write an encrypted transient cookie on the client. | ⚠️ **Medium**: Adds complex encryption overhead on the frontend. | Excellent |
| **3. In-Memory React Context** | Capture `currentPassword` as a transient variable `tempPassword` inside the `AuthProvider` state. It is never persisted to disk and cleared immediately on update or route change. |  **High**: Extremely secure. Value resides purely in-memory and disappears instantly upon browser tab closure, redirection, or state clear. | Excellent |

### Selected Decision
We selected **Option 3 (In-Memory React Context)**. It perfectly satisfies the backend's need for the current password while delivering a seamless, secure UX that complies with strict security guidelines (no persisting raw passwords on disk).

---

## 2. Dynamic Redirection and Route Guards

Upon successful authentication to `POST /api/auth/login`:
1. The backend returns `passwordConfirmed: false`.
2. The `login()` method inside `AuthContext.tsx` captures the typed password and stores it transiently in an in-memory state variable `tempPassword`.
3. The user's profile is saved in `localStorage` with `passwordConfirmed: false`.
4. The router guards detect `passwordConfirmed === false`. Any attempt to access `/dashboard` triggers an automatic redirect to `/force-password-change`.
5. The `/force-password-change` screen reads `tempPassword` from context to execute the change, then logs out the user, clearing the transient memory instantly.
